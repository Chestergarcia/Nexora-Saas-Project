THE PRODUCT OPPORTUNITY / OPORTUNIDAD

Make everyday store operations easier to understand.

Small-store work can involve switching between sales summaries, order lists, and product records. Nexora explores a single workspace where these core tasks are easy to find and connected through consistent navigation.

Maaaring palipat-lipat ang maliit na negosyo sa sales summary, order list, at product records. Sinusubukan ng Nexora ang iisang workspace kung saan madaling hanapin ang mga pangunahing gawain at pare-pareho ang navigation.

Design framing, not a research claim.This is a portfolio concept and front-end demo. No formal user interviews, usability study, or production analytics are represented here.Design framing ito, hindi resulta ng research. Portfolio concept at front-end demo ito; walang ipinapakitang pormal na interview, usability study, o production analytics.

A

New user / Bagong user

Sign up → onboarding → dashboard. The form checks required fields and a minimum 8-character password. The email and display name are stored locally; the password is deliberately not stored. A duplicate local email is directed to sign in.

Sign up → onboarding → dashboard. Chine-check ang required fields at minimum 8 characters ang password. Local na sine-save ang email at pangalan; hindi sine-save ang password. Kapag duplicate ang email sa browser, pinapapunta sa sign in.

B

Returning user / Bumabalik na user

Sign in → workspace check. In this front-end demo, sign-in checks whether the entered email matches the locally saved account; there is no real password validation. If the account has a workspace, open it. If not, begin onboarding.

Sign in → check ng workspace. Sa front-end demo, chine-check kung tugma ang email sa local account; walang totoong password validation. Kung may workspace, buksan ito. Kung wala, simulan ang onboarding.

C

Workspace setup / Setup ng workspace

Step 1 name required; step 2 category required; step 3 goal optional. Currency starts at USD and can be changed. Creating the workspace adds example order and product records so the dashboard is not empty.

Kailangan ang pangalan sa step 1 at category sa step 2; optional ang goal sa step 3. USD ang default currency at puwedeng palitan. Nagdadagdag ng sample order at product para may laman agad ang dashboard.

D

After onboarding / Pagkatapos ng onboarding

Dashboard → task section → manage records. Orders can be created, status-updated, and deleted; products can be added and deleted. The workspace picker switches between workspaces or starts setup for another one.

Dashboard → section → ayusin ang records. Puwedeng gumawa ng order, magpalit ng status, o mag-delete; puwedeng magdagdag at mag-delete ng product. Sa workspace picker, puwedeng magpalit o gumawa ng panibagong workspace.

Not implemented as a real service / Hindi totoong service: Forgot password only displays a demo notice—no email is sent. Authentication, cloud sync, real payments, and shared multi-user data are outside this prototype. Clearing this browser’s site data may remove the local demo workspace.
Demo notice lang ang forgot password—walang email na ipinapadala. Wala sa prototype ang totoong authentication, cloud sync, payments, at shared multi-user data. Maaaring mabura ang local workspace kapag ni-clear ang site data ng browser na ito.

05 / DESIGN RATIONALE

Why these decisions?

Intentional choices and trade-offs in the current prototype.
Mga sinadyang desisyon at trade-off sa kasalukuyang prototype.

01

Dashboard first / Dashboard muna

A summary gives the user a starting point before they open detailed records.
Buod muna bago pumunta sa mas detalyadong records.

02

Progressive onboarding / Paunti-unting setup

Three short steps split setup into workspace, business type, and personal focus.
Hinahati sa tatlong maikling hakbang ang setup.

03

Persistent navigation / Pare-parehong navigation

A stable sidebar keeps the six key destinations easy to recognize.
Madaling makilala ang anim na pangunahing section sa iisang sidebar.

04

Visible feedback / Kitang feedback

Validation and confirmations make the outcome of an action easier to understand.
Mas malinaw ang resulta ng aksyon kapag may validation at confirmation.

05

Responsive adaptation / Pag-angkop sa screen

The sidebar becomes a mobile menu and content cards stack on narrow viewports.
Nagiging mobile menu ang sidebar at nag-i-stack ang cards sa maliit na screen.

06

Honest prototype scope / Tapat na demo limits

Local-only storage is explained rather than presented as cloud-backed SaaS.
Nililinaw na local storage lang ito, hindi cloud-backed SaaS.
